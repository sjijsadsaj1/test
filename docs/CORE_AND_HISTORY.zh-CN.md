# 核心流程与历史方案保留说明

维护日期：2026-10-27。此文件解释保留什么、移除什么和为什么；进展看计划书，数据与修改看修改日志。

## 当前主流程

真实RGB/深度/位姿 → 原检测器及MobileSAM、BLIP → 物品地图/占据地图/语义地图 → 原地图frontier候选 → 可选物品词表概率 → 规划执行 → 新观测。

- 目标识别仍由原检测与融合系统负责；概率预测不产生真实目标点云、不授权STOP。
- 5×5最大语义值规则保留；该分数不是裁剪图的直接评分。未进行“改用最高分对应照片”的算法修改。
- 原地图输出二维frontier簇；`frontier_crop.py`用真实位姿、深度和0.15—1.8米高度先验投影，选择支持像素较多且较新的历史视角。目前仅支持水平视角；投影不是原版RGB门洞分割。
- `frontier_dictionary.py:PROMPT`接收完整真实观测和可用的裁剪，区分可见证据与未知空间推测。不告知模型当前搜索目标，要求21类独立概率，禁止归一化。
- 无有效裁剪时允许标明不可见、仅依上下文推测。窄裁剪通过中性留白满足模型输入要求；不伪造场景像素。
- 每次最多3候选，逐候选模型调用。漏项只补问缺失值，不将缺项填零，不重写已有有效值。
- 用当前目标概率选择已评分且可达候选；同分再看原地图分数和路径长度。不是BLIP与概率1:1混合，不使用生成图奖励。
- 初始化、探索分支资格、新查询检查、调用预算、查询身份和C++ ACK保留。临时概率不永久写回语义地图。有效改路保留原有最多6步路线承诺及安全中断。
- 实际成功仍由Habitat独立判定；MP3D当前为STOP且到有效目标view_points最短可通行路径距离严格小于0.2米、最多500步。真值只用于离线分析。

## 工作区保留的核心改动

|组件|作用|与原版的区别|
|---|---|---|
|同步观测服务|任务/step绑定、深度/位姿/检测一次提交、对应动作返回|原版仍使用异步ROS消息|
|A*确定性搜索预算|减少墙钟运行速度对搜索截断的影响|同步实验使用节点扩展预算|
|TSP服务恢复|检查调用失败、结果与恢复|工作区修复保留|
|疑似搜索点确认|未确认目标到点后最多4步真实观察，仍未确认则暂排除；默认开启|不是VLM主动复核；不会识别已高可信融合的书架其实非柜子|
|候选身份与临时评分接口|避免过期或身份错配的结果执行|历史世界模型接入所需公共基础|
|真实轨迹及诊断|保存查询、实际动作、ACK、位姿与输入输出|只记录，不以真值改变导航|
|独立原版下载与校验|锁定449源文件及允许的兼容补丁|用于原版对照，不能用工作区off冒充|

保留兼容代码不等于开启旧实验，也不意味着该方案已有效。此次没有更改模型提示词、概率、调用次数、评分权重、导航参数、成功阈值或随机种子。

## 可用入口

- 原版：`run_upstream_apexnav.sh`、`prepare_upstream_baseline.sh`、`verify_upstream_baseline.py`。
- 词表：`run_frontier_dictionary_smoke.sh`、`run_frontier_dictionary30.sh`；原中断例工具`run_frontier_dictionary_validation.sh`保留，但成本高，不默认运行。
- 已有输入复测：`probe_frontier_dictionary.py`、`replay_frontier_dictionary.py`，仅用户主动执行时调用VLM。
- 只读诊断：`perception_frame_replay.py`、`audit_stop_mesh.py`、`stop_evidence.py`。语义渲染像素须额外校验，不能把全零值直接当实例标签。
- 四组复核历史回归：`run_target_review_pilot.sh`，保留但不作为当前推荐实验。
- 共用函数：`experiment_utils.py`负责结果解析和端口选择；`probability_contract.py`负责概率值检查和请求哈希。

项目主入口与共享C++没有因清理改写。工作区无模型模式仍可能不同于隔离原版。
